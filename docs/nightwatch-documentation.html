☽ Nightwatch

A dependency-free cybersecurity toolkit — phishing detection, pcap traffic analysis, honeypots and log correlation. Version 0.2.0
Python: 3.9+  |  Dependencies: none (standard library only)  |  Tests: 46 (pytest)  |  License: MIT

1. Overview

Nightwatch is a modular cybersecurity toolkit that runs on nothing but the Python standard library. It detects phishing links and emails, analyzes raw packet captures for scanning, C2 beaconing and suspicious traffic, runs decoy honeypot servers that fingerprint attackers, and hunts red flags in server logs — all through a single CLI and an optional browser dashboard.

Modules

ModuleWhat it does
phishingHeuristic URL/email scoring (typosquatting, punycode homographs, URL shorteners, credentials in URL, suspicious TLDs) plus live verification: DNS resolution and redirect-chain following.
networkHand-rolled .pcap parser with TCP flow tracking (handshake completion), HTTP request/response extraction, DNS query extraction and C2 beaconing detection (periodic same-peer traffic).
honeypotTCP and HTTP decoy servers that log every connection and fingerprint attackers (suspicious path probing, brute-force patterns).
logsCollects JSON/JSONL/CSV/syslog/plain-text logs, correlates them with built-in or custom JSON rules, detects bursts and writes markdown reports.
webSOC-style dark dashboard served by a stdlib-only HTTP server. No framework, no build step.

3. Command Line Reference

phish — phishing detection

python -m nightwatch.cli phish --url <URL> [--verify] [--json]
python -m nightwatch.cli phish --file <email.txt> [--json]
OptionDescription
--urlURL to score (0–100 risk score).
--fileText file (email body) to scan; every link inside is scored.
--verifyLive verification: resolve the domain via DNS, follow the redirect chain manually and report the final destination.
--jsonMachine-readable output.

Exit codes: 0 = safe, 1 = suspicious/phishing, 2 = usage error — CI-friendly.

pcap — traffic analysis

python -m nightwatch.cli pcap <capture.pcap> [--json]

Output includes packet/protocol counts, unique and completed (fully handshaken) connections, websites visited (HTTP Hosts), user agents, DNS queries, possible C2 beacons and severity-ranked findings.

honeypot — decoy servers

python -m nightwatch.cli honeypot --http --port 8080
python -m nightwatch.cli honeypot --port 2222 --respond "220 fake ftp" --out honey.jsonl
OptionDescription
--hostBind address (default 0.0.0.0).
--portListen port (default 8080).
--httpFake HTTP server instead of raw TCP.
--respondText to send back to each TCP client (banner).
--outJSONL log file (default honeypot.jsonl).

logs — log analysis

python -m nightwatch.cli logs <file-or-dir> [--rules <rules.json>] [--out report.md] [--json]
OptionDescription
--rulesJSON file with custom detection rules (see section 6).
--outWrite a markdown report to this path.
--jsonMachine-readable output.

web — dashboard

python -m nightwatch.cli web [--host 127.0.0.1] [--port 8000] [--no-browser]
Port 8000 may already be in use on your machine; use --port 8001 to pick a free port.

4. Web Dashboard

The dashboard is served by a stdlib ThreadingHTTPServer — no Flask, no npm, no build step. Open the printed URL in a browser.

TabFeatures
PhishingCheck a link or paste an email. Optional live verification checkbox: shows resolved IPs, the full redirect chain, the final destination and a warning when the link crosses domains.
TrafficUpload a .pcap: packets/connections/established-connection stats, protocols, top sources, destination ports, websites visited, DNS queries, possible C2 beacons and findings.
HoneypotStart/stop TCP or HTTP decoys, watch live connections every 2 s, clear logs and run attacker fingerprint analysis.
LogsUpload JSON/JSONL/CSV/syslog/text logs; view findings and bursts; download a markdown report.

5. Findings Format

All modules report suspicious activity in one unified shape:

{
  "severity": "HIGH",      // HIGH | MEDIUM | LOW
  "label": "possible-beacon",
  "count": 6,              // number of involved events
  "detail": "10.0.0.1 -> 203.0.113.9:443 at ~5s intervals"
}

Detection labels

ModuleLabelSeverityMeaning
networksyn-scanHIGHA source sent SYN probes to 3+ distinct ports.
networkicmp-sweepMEDIUMICMP echo probes to 5+ destinations.
networksensitive-port-trafficMEDIUMTraffic to admin/database ports (23, 445, 1433, 3306, 6379, 27017, 3389, 5555, 1337, 5900).
networkpossible-beaconHIGH5+ packets to one peer at near-regular intervals (<30% variance).
honeypotsensitive-path-probingHIGHAttacker hit sensitive paths (admin, wp-login, .env, etc.).
honeypotbrute-force-patternMEDIUM5+ requests from a single source.
logsfailed-login, sql-injection, xss, path-traversal, privileged-account, forbidden-access, malware-indicator, invalid-user, denied, …—Built-in regex rules over normalized log messages (see DEFAULT_RULES).

6. Custom Log Rules

Rules are regex patterns with a severity and a label, supplied as a JSON list:

[
  {"pattern": "token expired", "severity": "HIGH", "label": "token-expiry"},
  {"pattern": "disk full",     "severity": "LOW",  "label": "disk-space"}
]
python -m nightwatch.cli logs app.log --rules rules.json --out report.md

Rules match case-insensitively against the message. A rule without a pattern is rejected with an error.

7. Phishing Scoring

URLs are scored 0–100; verdicts: safe (0–39), suspicious (40–69), phishing (70+). Signals include:

  • Brand typosquatting via Levenshtein distance (paypai → paypal, goolge → google)
  • Punycode homograph domains (xn--…)
  • URL shorteners (bit.ly and similar, score 40)
  • Credentials embedded in the URL (paypal.com@evil.io)
  • IP-literal hosts, hyphenated domains, suspicious TLDs
  • Phishing keywords in path/host (verify, login, secure, account…)

Live verification (--verify) resolves the domain, walks the redirect chain without following it blindly, and flags cross-domain redirects — so a "safe-looking" short link that lands on a different domain is exposed.
